修复 A/B/C/D 逻辑正确：

## 3. 质疑文档自身需修正的 2 处

### 3.1 §4 P1-新"跨帧 pinned buffer 复用"机理不准（建议降级/改写）

FULL replay 时 **Python 不重跑**：`lru_topk_indices_cpu` 等 planner 输入由**图内捕获的 D2H 节点**在 fused_plan_stream 上刷新（同流有序），不存在"Python 覆盖 pinned buffer vs callback 未完成"的竞争；piecewise replay 的 Python 侧 D2H 是阻塞拷贝（非异步），同样安全。**真实暴露面**只有：`enable_enpu` / draft-eagle 跳过 replay 前 synchronize 时，`update_stream` 上的**设备侧**注意力元数据写入与图重放的排序（与本次修复无关的独立问题）。

### 3.2 §4 `full_kv_cache .contiguous()` 快照候选：可静态判定，且是"修复不完整"的唯一真实条件分支

Mooncake 的 host 视图来自 1-D `narrow` + `reshape`，**恒连续** ⇒ `.contiguous()` 是 no-op，候选在 Mooncake 上不成立（可在启动时加一条 `data_ptr()` 断言固化）。但需注意：**若视图真的非连续**，快照拷贝发生在 Fix B 的 wait **之前**入队 ⇒ 快照可能拍到未写完的行 ⇒ 修复 B 不覆盖该形态。建议把断言加入验证清单（低成本、可立刻做）。
